# 麻将算账助手 · Mahjong Tally Helper

> 打完麻将时，在网页中输入每人的**终局分、台费垫付**，就能一键算清**每人应收/应付多少**，并给出一组简洁的转账方案，用户照着结果转账即可。
>
> 🔗 在线使用：<https://mahjong-tally-helper.app.workbuddy.host/>  (已失效，等待重新上线)
> 📦 形态：纯静态单文件网页，手机浏览器直接打开，无需下载、无需注册。

---

## 一、问题背景

麻将局结束后，最难的是**算账**：

- 每个人只记得自己最终的**终局分**，但「谁该给谁转多少钱」要同时考虑**输赢**和**台费垫付**；
- 台费由某人先垫付，其他人要平摊，还可能有人被**免除**台费；
- 转账笔数一旦多了，不仅麻烦，还容易转错，。

人工算容易出两类错：

1. **算不清**（台费进一法余数、垫付人兼输家等组合，人脑极易错）；
2. **算不简**（同样结清，却走了 5 笔而不是 3 笔，多出来的转账全是无效操作）。

这个工具把上述所有变量收进一个表单，输出两份东西：**每人合并净额（应收/应付大字）** 与 **一组最少笔数的转账清单**。

## 二、技术方案

### 2.1 整体架构：纯静态单文件

| 项       | 选择                                                           | 原因                                                    |
| ------- | ------------------------------------------------------------ | ----------------------------------------------------- |
| 技术形态    | 纯 HTML + CSS + 原生 JS，**单文件**，无后端、无构建工具                       | 算法完全在本地可算，零工具链故障；可直接部署为静态站点发微信群；`file://` 双击也能用       |
| 唯一编辑源   | `index.html`                                                 | 上线前一键 `node scripts/build_publish.mjs` 剥离调试入口，生成干净发布版 |
| 算法单一事实源 | `src/settle.js` + `src/brute.js`（node 自测用），`index.html` 内联副本 | 单文件可离线打开，同时保留可跑的回归测试                                  |

### 2.2 核心算法

1. **输入即净额来源**：`净额(元) = (终局分 − 初始分) × 分值换算`。只记终局分、不记过程流水。
2. **强校验做第一道防错**：`Σ终局分 == 人数 × 初始分`。只要它成立，各人净额之和**自动精确为 0**，无需二次校验。
3. **金额内部用整数「分(cent)」**：`K = 分值换算 × 100` 必须为整数（精确到 0.01），`净额(cent) = (终局分 − 初始分) × K`——`Σ净额(cent)` 恒为 0 是**数学保证**，不是浮点近似。
4. **最少转账笔数**：对合并净头寸跑最少有向边数优化，**笔数恒 ≤ n−1**（n 为人数，2–6 人）。
   - 生产用**暴力精确枚举**求真实最少（n≤6 瞬时完成）；
   - 同笔数下用 **O2（护胜者）** 偏好破 tie：让最大赢家「只收不付」，符合「我赢了大家给我」的直觉。
5. **台费并入输赢统一优化**（关键设计）：台费先用星型算出每人「台费净负担」，再**并入输赢净额**一起求最少笔数。合并后玩家间净额恒零和，可安全统一优化；方向相反的两笔（如 A 欠 B 输赢、B 欠 A 台费）会**自然抵销为单向**，进一步省笔数。

### 2.3 台费模型（本版唯一垫付人）

- 非垫付人按**进一法到 1 角**多摊，垫付人吸收余数、必然付得最少；
- 垫付人可同时被「免除」（真免除：付 0 台费，仍收回垫付全额）；
- 最终结果**只展示合并后的最少方案，不单列任何一笔台费账**。

### 2.4 验证关卡（防「静默算错」）

> 转账方案通常不唯一，所以验收**只比对「笔数」与「资金守恒」两项**，不比对具体配对。

- 7 条 node 自测全绿：算法对拍 85/85、TC-01~12 验收 15/15、重名不串算、O2 护胜者随机 2000 局、渲染 25/25、负分局 12/12、换算 10/10；
- 边界用例 30/30（台费除不尽进一法、合计不符拦截、非法输入提示等）。

## 三、亮点

- **一屏算清**：填完即出「应收/应付大字 + 转账清单」，移动端专门做了相对倍率排版，不同手机都能一屏看完结算页。
- **最少笔数且直觉合理**：笔数恒 ≤ n−1；同笔数下优先「赢家只收不付」，不出现「赢家当转账中转」的反直觉方案。
- **台费不单列账**：输赢与台费合并后只给一组净额，朋友照转即可，无需理解内部拆分。
- **零和数学保证**：整数 cent 运算 + 强校验，资金守恒是硬前提，杜绝「看着对其实错」。
- **零门槛**：纯静态、单文件、无注册；一键复制**文字版战报**直接发微信群。
- **容错友好**：合计不符、填了小数/非数字、台费全免除等异常都有明确提示，绝不静默取整。

## 四、界面速览 / 截图

页面自上而下三块（输入与输出严格分离）：

1. **牌局设置**：牌局日期、结算时间（自动带出）、分值换算（预设一毛底/五毛底/一块底 + 兜底）、起始分。
2. **对局表现**：2–6 名牌手的姓名、终局分、台费「垫付」单选、「免除」多选。
3. **终局结果**（点「生成结果」后展开）：
   - 🏆 **战绩榜单**：每人净得分（红=输/绿=赢，按中国习惯）+ 应收/应付大字 + 局内输赢与台费明细小字；
   - 💸 **转账方案**：`谁 → 谁 金额` 卡片列表 + 「共 N 笔」；底部「📤 导出战报」一键复制文字版。

## 五、我做了哪些决策

> 完整决策记录见 [`DECISIONS.md`](./DECISIONS.md)（D-001 ~ D-022）。以下为面向读者的精炼版。

**关于「输入什么」**

- **只记终局分，不记过程流水**（D-001）：终局分是牌桌上天然会记录的东西（数筹码即可），且自带强校验 `Σ终局分 == 人数 × 初始分`，比「净额之和为 0」更易被用户自行发现错误。
- **终局分允许负整数、完全开放**（D-012 / D-021）：输光初始分后又拿筹码的真实负分局必须能录入；定稿为「无提醒、无二次确认、直接计算」，仅保留零和校验作安全网。
- **金额内部一律用整数分(cent)**（D-008）：彻底规避浮点误差，零和成为数学保证而非近似。

**关于「怎么算」**

- **允许任意两两转账**（D-002）：一人可同时向多人转、也可同时从多人收，符合微信转账真实操作，且「最少笔数」有严谨数学解。
- **生产用暴力精确枚举，而非贪心**（D-005 / D-017）：M2-7 对拍发现贪心在约 0.2% 对称局会**多算 1 笔**（错了也看不出来）。为兑现「最少笔数」承诺，改用暴力精确枚举（n≤6 成本可忽略），把「我觉得对」变成「可证明对」。
- **O2 改为「护胜者 / 输赢直觉优先」**（D-014 / D-020）：初版「照顾最大败者」会让全局最大赢家当转账中转（反直觉），故整体删除败者照顾层级，改为让最大赢家「只收不付」。不增加任何一笔总转账。
- **重心由「最少笔数最优」迁移到「合并净额清晰展示」**（D-016）：24 万局实证 4–6 人局 90%+ 天然为 n−1 笔，「求全局最少」工程收益极小；用户真正算不清的是台费并入后的合并净额，所以把它做成产品主角。

**关于「台费怎么处理」**

- **台费并入输赢统一优化，不单列账**（D-007 / D-009）：星型算清每人台费净负担后并入输赢，方向相反的两笔自然抵销，省笔数且朋友无需理解拆分。
- **垫付人可同时被免除**（D-018）：真实场景里垫付人常输得最多又被免台费，按真免除处理（付 0 台费、仍收回垫付全额）。

**关于「工程与发布」**

- **纯静态单文件、无后端**（D-003）：零构建 = 零工具链故障，M1 就能打通部署，便于发微信群。
- **内部用唯一 key 计算、重名不串算**（D-019）：UI 层把玩家重映射为 `p1..pN` 恒定唯一键，输出再贴回显示名，两人重名也互不串算。
- **M6 上线部署与发布域名**（D-022）：以干净发布镜像经静态托管上线，子域直取 `mahjong-tally-helper`，覆盖历史 beta 链接。

## 六、使用说明

1. 打开 [在线链接](https://mahjong-tally-helper.app.workbuddy.host/)；
2. 填牌局日期、分值换算、起始分，逐人填终局分；有台费则填金额并指定垫付人、勾选免除名单；
3. 点「生成结果」→ 看战绩榜单与转账方案 → 点「📤 导出战报」复制文字版发微信群。

> 本地调试：`index.html` 含「载入示例牌局」按钮，可一键填充样例数据预览结算效果（发布版已剥离该入口）。
